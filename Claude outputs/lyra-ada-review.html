Fix first (P1)

  1. Tree Menu: role="tree" and role="treeitem" sit on the ul/li elements, but the buttons inside them take focus. Arrow keys, Home and End do nothing, every item is its own Tab stop (12–30 per story), and aria-expanded is on the button instead of the treeitem. 4.1.2 Name, Role, Value
  2. Left Nav: Same tree/treeitem misuse as Tree Menu, because it's built on it. 4.1.2
  3. Tags Input: Tab is one of the default addKeys and is intercepted even when the input is empty, so focus never leaves. Shift+Tab is also stuck. 2.1.2 No Keyboard Trap
  4. Overlay: In overlay.tsx, onEscapeKeyDown calls preventDefault() whenever closeOnBackdropClick is false. Three of the five stories can't be closed with Esc. 2.1.1 / WAI-ARIA dialog
  5. Sparkline: No role, aria-label or fallback text on the canvas wrapper. 1.1.1 Non-text Content
  6. Table: The column resize handle is a Tab stop with no visible indicator. focus-visible:bg-… applies to a 2px strip that doesn't render visibly. 2.4.7 Focus Visible
  7. Page Header: In "Panel Toggle (Overlay on Hover)", the hidden panel's resize handle is the first Tab stop. It's 8px wide with no visible focus. 2.4.7 / 2.4.3

None of the P1 fixes changes how anything looks in agent-next-gen-v3. The Tree Menu/Left Nav, Table resizer and Page Header fixes change only keyboard and screen-reader behavior. The others are in components v3 doesn’t use.

Cross-cutting

  • Focus after removal. Tag, Filter Chip and Tag Picker all drop focus to the page body after an item is removed or the popup closes. Add one shared rule: move focus to the next item, or to the container if none is left.
  • Tiny × buttons. Tag, Tag Picker and Tags Input use 12px remove targets. A single shared 24px hit-area utility fixes all three without changing how they look.
  • “required” is visual only. Email, Phone and Password inputs show an asterisk but never tell assistive tech the field is required. It’s the same one-line fix in each.
  • Searchable popups. Tag Picker and the Phone country list highlight options visually but don’t expose aria-activedescendant. A shared combobox pattern would fix both.
  • Focus style drift. Number Field and Tags Input use a 1px border color change, while everything else uses the 2px keyboard ring.

Announces itself as a tree but behaves like a list of buttons. Screen reader users are told to use arrow keys that do nothing.

  • Parents use aria-expanded and the active page uses aria-current="page"

Findings

How this was tested

A fresh Storybook build of lyra-ui was driven in headless Chromium (US English, reduced motion). For each of the 132 stories in the 21 components, including any Variants pages, the review ran axe-core 4 (WCAG 2.0–2.2 A/AA + best practice) and recorded the full Tab order. It compared focused against blurred styles to detect missing focus indicators and flagged Tab cycles (traps). It also tested Enter/Space activation, the effect of ↓ → ↑ Home End and Esc, focusable targets under 24px, and pointer-only clickable elements. Every finding above was then re-checked with targeted scripts (key-by-key value changes, aria wiring, focus after close or remove) and screenshots. The source was read to confirm the cause. Limits: no screen reader was run, so announcements are inferred from the ARIA. Contrast of disabled elements is reported but exempt under 1.4.3. Target-size calls use the 2.5.8 spacing exception.
